Rift v3 ceremony helper

Generates a real Google id_token and / or a real Passkey assertion bound to a specific user-op hash, then emits the curl command to send it to the parent-proxy.

Configuration

The hash is what the enclave will sign. Google will sign it into the id_token's nonce claim; the passkey assertion will sign it as challenge.

Google OIDC ceremony

Click "Sign in with Google" below. The nonce parameter is set to the user-op hash above, so the resulting id_token is bound to that exact transaction.

Passkey ceremony

  

    
Two stages. First "Enrol passkey" creates a credential and gives you the curl for /generate-wallet. Then "Sign with passkey" produces an assertion challenged with the user-op hash and gives you the curl for /sign.


    

      

        
        
      

      

        
        
      

    


    
    
    


    
    


    
    


    

      
      
    

    

  


  

    
Notes

    
    
      
  • This page is read-only locally — no network calls except to Google's GIS endpoint.
    • 
      
  • Curl commands target the parent-proxy URL above. Default http://127.0.0.1:7777 means "paste the curl on the EC2 itself"; change it to e.g. http://<EC2-public-IP>:7777 to run from your workstation.
    • 
      
  • The Bearer token never leaves this page — it just gets templated into the curl string for you.
    • 
      
  • For Passkey, this page uses RP-ID = localhost by default (matches the enclave's WebAuthn policy entry).
