# Self-host the Rift signer enclave

For institutions (banks, fintechs) deploying Rift's signing infrastructure into their own AWS account.

At the end, you own — in your AWS account, in your region — a hardened Nitro Enclave that signs UserOps on behalf of your users, and a KMS key whose plaintext only that specific enclave can retrieve. Rift never sees your users' keys. If you turn off your AWS account tomorrow, the signing goes dark. That's the point.

**What you DON'T deploy anymore:** the Node smart-wallet parent. Rift's centralized smart-wallet resolves your project's routing (parent-proxy URL, bearer, KMS ARN, per-chain bundlers) from Rift's DB on every request. Your infra is only enclave + parent-proxy + nginx + KMS.

---

## Architecture

```
┌────────────────────────────────┐        ┌───────────────────────────────┐
│ RIFT (multi-tenant, centralized)│        │ INTEGRATOR (per-project, self-hosted)
│                                │        │                               │
│  backend  ──────────────►  smart-wallet ─► ALB :443 ── nginx :8080 ──► parent-proxy :7777 ──vsock──► enclave (Nitro)
│    │                          │                    │                           │
│    └── ProjectEnclaveConfig ──┘                    │                           └──► KMS Decrypt-with-Recipient (PCR0 gate)
│        (parent_proxy_url,                          │
│         bearer, kms_arn,                           │
│         pcr0, per-chain configs)                   └── Bearer verified here
│                                                       (shared with Rift on registration)
└────────────────────────────────┘
```

## What Rift ships and what you provide

| | Rift ships | You provide |
|---|---|---|
| Enclave source (Rust) | ✅ (public, pinned tag) | — |
| Parent-proxy source (Rust) | ✅ (same repo) | — |
| Canonical PCR0 per tag | ✅ (published at `riftfi.com/enclave/pcr0/<tag>`) | — |
| Backend + smart-wallet (centralized) | ✅ (managed by Rift) | — |
| AWS account, region, VPC | — | ✅ |
| KMS CMK, IAM role, EC2 | — | ✅ (created by `aws-provision.sh`) |
| nginx + ALB + ACM cert + DNS | — | ✅ |
| Bearer token for Rift → your parent-proxy | — | ✅ (generated by `ec2-bootstrap.sh`, shared with Rift on registration) |
| Per-chain bundler API keys + RPC URLs | — | ✅ (submitted to Rift's admin API) |

You submit your parent-proxy URL + bearer + KMS ARN + PCR0 + chain configs to Rift's admin API once. From then on, whenever one of your project's users signs a transaction, Rift's smart-wallet resolves your routing from its DB and forwards the sign request to your parent-proxy with your bearer.

## Prerequisites (on the operator's laptop)

1. AWS CLI configured for the target account: `aws sts get-caller-identity`.
2. AWS Session Manager plugin.
3. IAM principal with `iam:*`, `kms:*`, `ec2:*`, `ssm:StartSession`.
4. This `prod-automation/` folder from `Rift-FI/Rift-secure-signing-enclave` at the same tag you intend to deploy.
5. Your Rift Admin API key (issued by Rift support) — you'll use it in step 9.

---

## Step 1 — Pick a Rift release to pin

Rift publishes released enclave versions as tags. Each has a canonical PCR0 at:

```
https://riftfi.com/enclave/pcr0/<tag>.txt
https://riftfi.com/enclave/pcr0/<tag>.json
```

Pick a tag (e.g. `v1.0.0`) — call it `ENCLAVE_REF`.

Do NOT run production against `main` — the PCR0 will drift.

---

## Step 2 — Provision AWS (sandbox)

```sh
cd prod-automation
export AWS_REGION=us-east-1        # or your data-residency region
ENV_TAG=sandbox ./aws-provision.sh
```

Creates: IAM role + instance profile + KMS CMK (placeholder policy) + security group + Nitro-enabled EC2. Prints instance ID, KMS ARN, role ARN.

Tighten the SG later: replace 443 open-to-world with your ALB's SG.

---

## Step 3 — SSM into the instance

```sh
aws ssm start-session --target <INSTANCE_ID> --region us-east-1
sudo su - ec2-user
```

---

## Step 4 — Bootstrap the enclave

Copy this folder onto the instance (heredoc via SSM or fork+clone). Then:

```sh
ENV_TAG=sandbox ENCLAVE_REF=v1.0.0 ./ec2-bootstrap.sh
```

Installs everything: nitro-cli, docker, rust, nginx. Configures the allocator. Clones + builds the enclave at your pinned tag. Prints the PCR0. Installs parent-proxy + nginx sidecar as systemd units. **Generates a fresh random bearer at `/etc/rift-nginx-bearer` (600, root).**

At the end you'll see:

```
  ref         : v1.0.0
  built sha   : <SHA>
  PCR0        : 0d3e4b8a…
  bearer file : /etc/rift-nginx-bearer
```

---

## Step 5 — Verify PCR0

```sh
./verify-pcr0.sh
```

`✓ MATCH` → the enclave you built is byte-identical to Rift's release. Proceed.

`✗ MISMATCH` → do NOT continue.

---

## Step 6 — Pin PCR0 into your KMS policy (MANUAL)

Locally:
```sh
sed -e "s|__ACCOUNT_ID__|<YOUR ACCOUNT ID>|g" \
    -e "s|__ROLE_NAME__|rift-signer-enclave-sandbox-role|g" \
    -e "s|__PCR0__|<PCR0>|g" \
    templates/kms-key-policy-hardened.json
```

Paste the output into AWS console → KMS → key policy → Save.

---

## Step 7 — Launch the enclave

```sh
cd ~/rift/Rift-secure-signing-enclave
sudo make run
CID=$(sudo nitro-cli describe-enclaves | jq -r '.[0].EnclaveCID')
sudo tee /etc/rift-parent-proxy.env >/dev/null <<EOF
ENCLAVE_CID=$CID
EOF
sudo systemctl restart rift-parent-proxy

# Local (behind nginx auth) health:
curl -s http://127.0.0.1:7777/health   # → "ok"

# Nginx bearer-authed:
BEARER=$(sudo cat /etc/rift-nginx-bearer)
curl -s -H "authorization: Bearer $BEARER" http://127.0.0.1:8080/health   # → "ok"

# ALB health path (no bearer needed):
curl -s http://127.0.0.1:8081/health   # → "ok"
```

---

## Step 8 — Frontend (ALB + ACM + DNS)

Manual, per your VPC + DNS conventions:

1. Request an ACM cert for `signer-sandbox.yourorg.com`.
2. Create an ALB with two listeners:
   - `:443` HTTPS (ACM cert) → target group on **:8080** (bearer-verified) → your instance
   - Health check target: separate target group on **:8081/health** (no bearer)
3. Point `signer-sandbox.yourorg.com` DNS at the ALB.
4. Tighten the EC2 SG: replace `0.0.0.0/0` on `:8080/:8081` with the ALB's SG.

---

## Step 9 — Register with Rift

Rift's backend admin API:

```sh
# 9a — the enclave config
curl -X PUT https://backend.riftfi.com/admin/projects/$PROJECT_ID/enclave-config \
  -H "x-admin-key: $RIFT_ADMIN_KEY" \
  -H "content-type: application/json" \
  -d '{
    "parentProxyUrl": "https://signer-sandbox.yourorg.com",
    "parentProxyBearer": "<bearer from /etc/rift-nginx-bearer>",
    "kmsKeyArn": "<your KMS ARN from step 2>",
    "kmsRegion": "us-east-1",
    "pcr0": "<PCR0 from step 4>",
    "enclaveRef": "v1.0.0"
  }'

# 9b — one entry per chain you want to support
curl -X PUT https://backend.riftfi.com/admin/projects/$PROJECT_ID/chain-configs/8453 \
  -H "x-admin-key: $RIFT_ADMIN_KEY" \
  -H "content-type: application/json" \
  -d '{
    "bundlerUrl": "https://api.pimlico.io/v2/base/rpc?apikey=<YOUR PIMLICO KEY>",
    "rpcUrl": "https://base-mainnet.g.alchemy.com/v2/<YOUR ALCHEMY KEY>",
    "paymasterUrl": null
  }'
```

`$PROJECT_ID` is your Rift project ID. `$RIFT_ADMIN_KEY` is issued to you by Rift support.

From this moment forward, any user whose `projectId = $PROJECT_ID` in Rift's DB has their sign / wallet-generation calls routed to YOUR enclave. Users on other projects are unaffected. Users on your project without an enclave config would fall back to Rift's default — but since you just added one, they don't.

---

## Step 10 — Sandbox soak (72h)

Watch for:
- `kms attestation rejected` errors (PCR0 mismatch)
- 401s from your nginx (bearer mismatch — the value in Rift's DB doesn't match `/etc/rift-nginx-bearer`)
- Enclave OOMs
- Any tx that failed to sign

Fix any of the above before graduating.

---

## Step 11 — Production

Repeat steps 2–9 with `ENV_TAG=prod`. Separate resources. Submit the prod bearer / URL / KMS to Rift's admin API against the same project ID or a distinct prod project ID — coordinate with Rift.

---

## Rotating the bearer

Whenever you want:

```sh
# On your EC2:
NEW=$(openssl rand -hex 32)
sudo tee /etc/rift-nginx-bearer >/dev/null <<< "$NEW"
sudo systemctl reload nginx

# From your admin machine:
curl -X PUT https://backend.riftfi.com/admin/projects/$PROJECT_ID/enclave-config \
  -H "x-admin-key: $RIFT_ADMIN_KEY" \
  -H "content-type: application/json" \
  -d '{ "parentProxyUrl": "…", "parentProxyBearer": "'$NEW'", … }'
```

There's a short window (up to 60s, matching the smart-wallet cache TTL) where in-flight signs may 401. Do this in a low-traffic minute.

---

## Rollback

- **Cut Rift traffic**: `DELETE /admin/projects/$PROJECT_ID/enclave-config`. Rift falls back to the default enclave for your users. Your instance keeps running unused.
- **KMS attestation misfire**: temporarily loosen the KMS policy to the placeholder template. Security downgrade — only for diagnosis.
- **Wipe and rebuild**: `sudo make kill && sudo make clean && sudo make eif && sudo make pcr0`. Update KMS policy with new PCR0. Update Rift admin config.
- **Terminate everything**: kill EC2, schedule KMS deletion (7-day reversible window), delete IAM role. Rift's config for you still points at the dead URL — do `DELETE /admin/projects/…/enclave-config` first to avoid failed signs during teardown.

## Common errors

| Symptom | Cause | Fix |
|---|---|---|
| Rift sends signs but they 401 | Bearer in Rift's DB ≠ your `/etc/rift-nginx-bearer` | Re-PUT the config with the correct bearer |
| Rift sends signs but they timeout | ALB → your instance connectivity | Check SG allows ALB, check nginx is running |
| `kms attestation rejected` | PCR0 in KMS policy ≠ enclave's PCR0 | Re-run `make pcr0`, update KMS policy |
| Enclave signs but Rift doesn't send anything | User's `projectId` in Rift's DB ≠ your project ID | Verify with Rift support |
| Nginx returns 404 for `/sign` | User hit `/sign/foo` or trailing slash | Rift only sends exact `/sign` — check your ALB rules |
| ALB health check flaps | Health probing `:8080` with bearer instead of `:8081` no-auth | Split the target groups per step 8 |
